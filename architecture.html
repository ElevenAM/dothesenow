Key Architecture Decision: Data Isolation
Your MCP server uses the service_role key, giving it full read/write to the marketing database. This is safe because the MCP server runs locally on your machine — only Claude Desktop talks to it via stdio.

Freelancers access the database through the Supabase client with an authenticated role, which is locked down by Row-Level Security policies. They can only see: open tasks (browsing), their own assigned tasks, their own submissions, and task-scoped messages. They cannot see: strategy documents, competitive analysis, CRM contacts, outreach logs, other freelancers' work, or campaign internals.

This means you can tell Claude "create a task for a freelancer to write 3 LinkedIn posts about therapist burnout based on our competitive positioning" and the MCP server will generate a clean brief from your strategy doc without exposing the underlying competitive intelligence to the freelancer.
