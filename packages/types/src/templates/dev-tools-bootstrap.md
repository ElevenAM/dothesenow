# Developer Tools Marketing Strategy — Bootstrap

## Goals
- Build developer trust through documentation and open-source presence
- Grow an engaged community of early adopters and contributors
- Achieve first 100 active developers through organic, community-driven channels

## Audience
- **Primary**: Individual developers and small-team leads evaluating tools for their stack
- **Secondary**: DevRel/platform engineers at mid-stage startups building internal tooling
- **Pain points**: Poor documentation, vendor lock-in, opaque pricing, missing integrations
- **Watering holes**: Hacker News, GitHub, Stack Overflow, Dev.to, Reddit (r/programming, r/webdev), Discord dev communities

## Channels
1. **Documentation/Tutorials** (type: owned) — Comprehensive docs, quickstarts, and integration guides. Primary metric: time-to-first-value, tutorial completion rate. Budget: 35%.
2. **Community** (type: owned) — Discord/Slack community, GitHub discussions, Stack Overflow presence, founder participation in forums. Primary metric: community questions answered, developer retention. Budget: 25%.
3. **Open Source** (type: earned) — Public repos, example projects, community contributions. Primary metric: GitHub stars, community PRs, adoption. Budget: 20%.
4. **Cold Outreach & Partnerships** (type: paid/earned) — Founder-led outreach to complementary tools and dev communities; early beta access partnerships. Primary metric: partnership signups, featured integrations. Budget: 20%.

## Content

### Pillars
- Getting-started guides and integration tutorials
- Architecture deep-dives and technical blog posts
- Changelog and transparency updates (build in public)
- Founder brand: founder's technical perspective, engineering decisions, community engagement

### Cadence
- Documentation: continuous (updated as product evolves, minimum 1 new guide per month)
- Technical blog: 4 high-quality deep-dives per 2 months, each repurposed into social posts and HN discussions
- Changelog: weekly transparency update (build in public)
- Community engagement: daily in Discord/GitHub/Stack Overflow

### Formats
- Interactive documentation site with runnable code examples
- Technical deep-dive blog posts (2000–3000 words)
- Architecture decision records (ADRs) in GitHub repo
- Weekly changelog or progress update (500–800 words)
- Example project repos (starter kits, reference implementations)

## Schedule

### Months 1–2: Documentation & Community Foundation
- **Actions**: Ship comprehensive documentation site with 5 quickstart guides. Launch Discord community. Publish 4 technical deep-dive blog posts. Create example starter projects on GitHub.
- **Success criteria**: Docs site complete with 50+ pages, 100+ Discord members, 4 blog posts published, 100+ GitHub stars on example repos, 50+ documentation visits/day.
- **Decision point**: Are developers able to get started without friction? Which docs/tutorials are most requested? Is Discord showing signs of engagement?

### Months 3–4: Integration & Visibility
- **Actions**: Create integration guides for top 5 requested tools. Start weekly "build in public" changelog. Actively engage in HN, Reddit, and Stack Overflow. Reach out to 5-10 complementary tools for partnership/integration.
- **Success criteria**: 5 integration guides published, weekly changelog consistency, 2-3 HN posts ranking (100+ points), 10+ Stack Overflow answers, 1-2 partnership discussions initiated.
- **Decision point**: Which integrations are driving adoption? Is "build in public" generating interest and trust? Are partnerships gaining traction?

### Months 5–6: Scale & Community Leadership
- **Actions**: Launch office hours (bi-weekly). Publish 4 more technical posts. Finalize 2-3 partnership integrations. Identify potential podcast/newsletter sponsorships in dev space.
- **Success criteria**: 30+ attendees per office hours, 500+ Discord members, 4 more blog posts, 2-3 live integrations, 200+ GitHub stars, 150+ monthly documentation visits.
- **Decision point**: Has the tool established developer trust? Is community engagement sustaining growth? Which sponsorships/partnerships drive the most qualified signups?
- **PMF Velocity Override**: If weekly signup growth >15% AND MRR >$500, graduate to Growth tier regardless of calendar phase. See `framework-selection-matrix.md` §PMF Velocity Override.
